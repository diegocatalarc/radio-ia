# Radio IA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un podcast privado diario en español (8-10 min) sobre IA e impacto económico, generado y publicado automáticamente.

**Architecture:** Un pipeline Python en cinco etapas (recolectar, deduplicar, escribir guion con Claude, voz TTS, publicar RSS) orquestado por `radio/run.py`. GitHub Actions lo ejecuta cada madrugada y publica `feed.xml` y los MP3 en GitHub Pages desde la rama `gh-pages`/carpeta `site/`.

**Tech Stack:** Python 3.12, `feedparser`, `httpx`, `trafilatura` (texto de artículos), SDK `anthropic`, `pytest`, GitHub Actions + Pages. TTS: proveedor elegido en Task 5.

**Spec:** `docs/2026-11-10-radio-ia-design.md`

## Global Constraints

- Idioma del episodio: español. Duración objetivo 8-10 min (~1300-1600 palabras habladas).
- Todo dato (cifra, fecha, nombre) debe salir de texto leído por el pipeline; el análisis se dice en voz como interpretación ("mi lectura es que...").
- Con paywall: solo titular y resumen del feed.
- Con menos de 2 historias relevantes: no se publica y el pipeline termina con código de salida distinto de 0 (GitHub avisa por correo). Con 2-3 historias: episodio corto.
- Un episodio con error se reemplaza; el siguiente guion incluye una corrección breve.
- Zona horaria y hora objetivo en un solo ajuste (`config.toml`): Chile (`America/Santiago`) hasta el 7 dic 2026; el cron de Actions (UTC) se programa varias horas antes de las 6 am locales.
- Repo público; feed no listado. Costo objetivo menos de ~1 USD por episodio.
- Secretos (`ANTHROPIC_API_KEY`, clave TTS) solo en GitHub Secrets, nunca en el repo.

## Review Focus

- Feed sin episodios aún: `feed.xml` debe ser RSS válido igualmente.
- Títulos con tildes, `&` o comillas: el XML debe escapar bien y no romper la app de podcasts.
- Historia sin cuerpo (paywall o extracción vacía): se usa solo titular/resumen y no se inventan datos.
- Guion demasiado largo para el límite del TTS: se parte en trozos y se unen los MP3 sin cortes.
- Ejecución repetida el mismo día: reemplaza el episodio del día, no lo duplica.
- Falla a mitad de camino (API caída): el feed publicado previamente queda intacto.
- Cambio de zona horaria: el nombre del episodio y la fecha usan la zona de `config.toml`.
